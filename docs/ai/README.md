# AI Retrieval Corpus

This directory contains the semantic knowledge used to resolve platform questions into API operations and frontend destinations.

## Retrieval Model

Retrieval uses a hybrid index:

- lexical scoring preserves exact endpoint names, identifiers, and university terminology;
- multilingual E5 embeddings retrieve chunks with similar meaning when the wording differs;
- PostgreSQL with `pgvector` stores document embeddings and performs cosine-similarity search;
- the two result sets are normalized, weighted, merged, and ranked before context is sent to the navigation agent.

Knowledge chunks are hashed. Embeddings are generated only for new or changed chunks and are reused from PostgreSQL after that. The original navigation question is embedded directly; no language-model call rewrites it first. The ONNX model runs locally in the Spring Boot process and is cached under the local development directory.

## Navigation Planning

The retrieved API and UI context is normally sent to DeepSeek once. The model chooses between two outcomes:

- `NAVIGATE` resolves the requested records and returns a validated management route.
- `ANSWER` resolves the requested data and returns a direct answer in the widget.

Both outcomes use a complete read plan rather than requesting one endpoint per model turn. The plan contains ordered GET steps, result matching, and bounded fan-out for parent collections. The backend executes the plan with the caller's token. Navigation plans resolve identifiers and validate the final route. For direct answers, every successfully resolved step is sent to a separate answer prompt so the identity and relationship chain is preserved. The answer context remains size-bounded and the answer prompt may use verified API data only.

Navigation normally uses one model call. A direct answer uses a planning call followed by one answer-generation call after the API reads succeed. If deterministic execution fails because the predicted query, response field, match, dependency, or route was inaccurate, the failed plan and completed response previews are sent back for one repair call. The repaired complete plan is then executed once. This restores limited response-aware adaptation without returning to one model call per API request.

If the initial context genuinely lacks a required endpoint or route, the plan may request one additional retrieval query. The backend retrieves that context and allows one final planning call. This is a bounded fallback, not the default execution path.

## Documents

- `api-knowledge.md` documents every implemented read-only backend operation, including exact path and query parameters, response identifiers, business use, matching rules, and cross-resource lookup workflows.
- `ui-navigation-knowledge.md` maps user destinations to frontend routes, route parameters, supported query parameters, and the API identifiers needed to build each route.

## Source Order

When documents disagree, use this order:

1. Spring controller mappings for implemented HTTP operations.
2. Frontend router files and page query-parameter handling for navigation.
3. Generated OpenAPI schemas for request and response field definitions.
4. Architecture and domain documents for terminology and relationships.

The backend API knowledge is audited against the OpenAPI document generated by the running Spring application. Controller and OpenAPI changes must update the knowledge document in the same feature change.

## Retrieval Boundaries

- AI navigation serves establishment Super Admins and Admins only.
- API knowledge explains what a GET operation means; OpenAPI remains the source for exact query and response schemas.
- The AI retrieval flow is read-only. Mutation operations are intentionally excluded from the corpus.
- UI knowledge describes management routes the current React application can open. It does not include root governance, professor, or student workspaces.
- UUIDs are never guessed. They must come from the conversation, current UI context, or an earlier API result.
- Academic labels such as `M1`, `S1`, or `2026-2027` are not identifiers. Resolve them through collection endpoints before building dependent requests or routes.
